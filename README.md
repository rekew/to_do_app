# To-Do App (F# + Elmish Land)

A small to-do app built to learn **F#** with **Elmish Land** — a framework for writing browser apps with Fable, React and Elmish.

> **Note on intent**
>
> This project is intentionally kept *simple* rather than *ideal*. It is not a showcase of best practices or production architecture. It is meant to be easy to read and reason about, so you can follow the code top to bottom and learn how F# and Elmish Land fit together. As you get comfortable, there are suggestions at the bottom for making it "more real".

## Features

- Add a task (button or Enter key)
- See all tasks in a list
- Update a task:
  - toggle it as completed (checkbox, with strikethrough)
  - edit its text inline (Save / Cancel, Enter to save)
- Delete a task

All data lives in memory only — a page refresh clears the list.

## Tech stack

| Piece | What it is |
| --- | --- |
| F# | the language everything is written in |
| Fable | compiles F# to JavaScript |
| Elmish | the Model / View / Update (MVU) state loop |
| Feliz | an F# DSL for building React UIs |
| React | the underlying rendering library |
| Vite | the bundler / dev server |
| Elmish Land | scaffolding that maps `src/Pages/` to routes and generates the glue code |

## Project structure

```
frontend/
├── src/
│   ├── Shared.fs            # app-wide state (SharedModel) — empty by default
│   ├── Domain.fs            # data types: the Todo record
│   ├── TodoState.fs         # the state machine: Model, Msg, init, update
│   ├── TodoView.fs          # all UI markup (rendering only)
│   └── Pages/
│       ├── Page.fs          # thin wiring: the page the app actually renders
│       ├── Layout.fs        # page wrapper (nav/chrome) — currently a pass-through
│       └── NotFound.fs      # 404 fallback
├── elmish-land.json         # elmish-land configuration
├── frontend.fsproj          # F# project file (compile order matters)
├── index.html               # entry point: mounts the app into <div id="app">
├── vite.config.js           # Vite config
├── Dockerfile               # builds a production image (nginx)
├── nginx.conf               # serves the built app with SPA fallback
├── docker-compose.yml       # one-command local run
└── .elmish-land/            # AUTO-GENERATED by elmish-land — don't hand-edit
```

### Where to look first

1. **`src/Domain.fs`** — the `Todo` record. Data types only, no behavior.
2. **`src/TodoState.fs`** — the heart of the app. `Model` is the state, `Msg` is every event the UI can produce, and `update` is a pure function that turns a message + old state into new state.
3. **`src/TodoView.fs`** — turns the model into HTML. Every button/input just calls `dispatch` with a message.
4. **`src/Pages/Page.fs`** — connects those three into something elmish-land can render. It's intentionally small.

## How it works (the Elmish loop)

```
         +------------------+    event      +--------------+
         |      Model       | <------------ |  User clicks |
         +------------------+               +--------------+
                |                                    ^
                v                                    |
         +--------------+    dispatch(Msg)   +--------------+
         |     view      | ------------------> |    update    |
         +--------------+   renders new state  +--------------+
```

- **Model** — the whole state of the screen (a list of todos plus UI input fields).
- **Msg** — every thing that can happen (`AddTodo`, `ToggleTodo`, `DeleteTodo`, ...).
- **init** — the starting state.
- **update** — a pure function: `Msg -> Model -> Model`. No side effects, no mutation.
- **view** — renders the model; user actions call `dispatch` with a message.
- **Elmish** re-runs `view` automatically whenever `update` returns a new model.

### Elmish Land's job

Elmish Land turns your **file structure** into **routes**: a file `src/Pages/Page.fs` becomes the `/` page, `src/Pages/About/Page.fs` would become `/about`. It generates everything under `.elmish-land/` (the router, the shared/layout/page wiring, and the bootstrapping code) when you run its CLI, so you only write your own pages and state.

## Prerequisites

- [.NET SDK](https://dotnet.microsoft.com/download) `10.0.301` or newer (see `frontend/global.json`)
- [Node.js](https://nodejs.org/) `20.19+` or `22.12+` (Vite 8 requirement)
- Optional: Docker for containerized runs

## Getting started

```bash
cd frontend
npm ci                    # install dependencies (dotnet tool + npm packages)
npm run start             # dev server with hot reload (dotnet elmish-land server)
```

`npm run start` starts the dev server (typically http://localhost:5173).

### Production build

```bash
cd frontend
npm run build             # dotnet elmish-land build -> outputs dist/
```

The built app lands in `frontend/dist/`.

## Docker

```bash
cd frontend
docker compose up -d      # builds and serves the app on http://localhost:8080
```

The `Dockerfile` is multi-stage: it builds the SPA inside a .NET SDK image, then serves the static `dist/` with nginx.

## Where to go next

Ideas to extend this app while you learn (roughly in increasing difficulty):

- Make todos **persist** across refreshes (localStorage)
- Add **filters** (all / active / completed)
- Move the todo state to **`Shared.fs`** so it survives route changes
- Add a second **route** (e.g. an "About" page) and see elmish-land generate it
- Split the page into a reusable **component** (Feliz hooks) or extract `TodoRow` into its own module
- Connect a **backend** (e.g. SAFE Stack style) and load todos from an API
